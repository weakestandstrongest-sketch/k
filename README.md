# CHRONOS ATELIER ― 時の宮殿

時間を「宮殿の中で動く精密な機械」として扱う、ブラウザで動くカレンダーアプリです。
React・TypeScript・Vite・Motion for React で作られ、予定はこの端末のブラウザ内（IndexedDB）に保存されます。
サーバー・ログイン・有料 API は使いません。

| 画面 | 名前 | できること |
| --- | --- | --- |
| 1 | **THE GRAND HALL**（ホーム） | 今日の日付・現在時刻・次の予定・残りの予定・残りの空き時間・24時間の時計盤 |
| 2 | **THE ORRERY**（カレンダー） | 日・週・月表示、日付移動、予定の追加／編集／削除、ドラッグでの時刻移動、重なりの検出 |
| 3 | **THE CHAMBER**（予定の詳細） | 予定を選ぶと広がる詳細パネル。題名・日付・時刻・カテゴリー・場所・メモ・準備・実施の記録・余白 |
| 4 | **THE EQUATION**（時間設計） | 空き時間の計算式、重なりの一覧、再編成の提案（適用前に比較）、空き時間の検索 |
| 5 | **THE CHRONICLE**（振り返り） | 日・週・月の集計、カテゴリー別の円環、計画と実績、時間の帯、過去の記録 |
| ― | **一日を閉じる** | 実際に行った予定を記録すると、それだけが星になり光の線で結ばれる「星図」 |

## 1. 動かし方（Windows）

### 必要なもの
- **Node.js 20 以上**（推奨: 22 LTS）… <https://nodejs.org/ja> から「LTS」をインストール
- エディタ（VS Code など）とターミナル（PowerShell で可）

### 初回だけ
```powershell
cd （このフォルダーの場所）
npm install
```
> `.npmrc` に `legacy-peer-deps=true` を設定しています。依存関係の警告で止まらないためのもので、そのままで問題ありません。

### 開発用サーバーを起動
```powershell
npm run dev
```
表示された `http://localhost:5173/` をブラウザで開きます。ファイルを保存すると自動で画面が更新されます。

### よく使うコマンド
| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発用サーバーを起動 |
| `npm run build` | 型チェック＋本番用ファイルを `dist/` に作成 |
| `npm run preview` | 作成した本番用ファイルを `http://localhost:4173/` で確認 |
| `npm run typecheck` | TypeScript の型チェックのみ |
| `npm run lint` | ESLint でコードを検査 |
| `npm test` | 単体テスト（Vitest）を実行 |

## 2. iPhone で使う

### 同じ Wi-Fi で試す（開発中）
```powershell
npm run dev -- --host
```
表示された `Network: http://192.168.x.x:5173/` を iPhone の Safari で開きます。
（この方法では Service Worker が動かないため、オフライン動作は確認できません。）

### ホーム画面に追加してオフラインで使う
PWA（ホーム画面への追加・オフライン動作）には **HTTPS で公開されたページ** が必要です。

1. `npm run build` を実行し、できた `dist/` フォルダーを HTTPS のホスティング（GitHub Pages、Netlify、Cloudflare Pages など）に置きます。`base: './'` にしてあるので、サブフォルダーに置いても動きます。
2. iPhone の Safari でそのページを開き、共有ボタン →「ホーム画面に追加」。
3. 一度開けば、その後は機内モードでも起動・閲覧・編集できます（データは端末内）。

**注意**: iPhone の Safari とホーム画面に追加したアプリは、保存領域が別々です。また iOS は長期間使われていないサイトのデータを削除することがあります。大切な予定は他の手段でも控えてください。

## 3. フォルダー構成

```
src/
  main.tsx              起動処理（React を描画し、PWA を登録）
  App.tsx               骨組み：Provider、画面の転換（円形の絞り）、重ねて表示するパネル
  pwa.ts                Service Worker の登録
  data/                 データ層（画面から独立）
    types.ts              予定・設定の型
    db.ts                 IndexedDB の薄いラッパー（失敗時は日本語のエラー）
    repository.ts         予定・設定の読み書き
    eventModel.ts         予定の作成・更新・入力チェック・変更履歴
    normalize.ts          保存データの検証（壊れたデータを読み込まない）
    sampleData.ts         初回起動時の見本データ
    categories.ts         カテゴリー（名前と色）
  lib/                  計算（純粋関数・テスト付き）
    date.ts               日付・時刻（タイムゾーンに依存しない暦の計算）
    schedule.ts           重なり・空き時間・列の割り当て・時間の内訳
    planner.ts            再編成の提案（決定的なルール）
    analytics.ts          振り返りの集計
    geometry.ts           24時間文字盤の座標
  state/                状態管理（React Context とフック）
    EventsContext.tsx     予定と設定（保存が成功してから画面に反映）
    AppContext.tsx        画面遷移・表示中の日付・パネルの開閉（URL の # と同期）
    MoveContext.tsx       予定を動かすときの確認の流れ
    ToastContext.tsx      通知
    ConfirmContext.tsx    確認ダイアログ
  motion/tokens.ts      モーションの語彙（イージング・時間）
  styles/               デザイントークン（tokens.css）と共通スタイル（global.css）
  components/           再利用する部品（時計盤、日付ベゼル、回転する数字、私室、フォームなど）
  screens/              各画面（GrandHall / Orrery / Equation / Chronicle）
```

### データの形（予定）
| 項目 | 説明 |
| --- | --- |
| `id` | 変わらない一意の ID |
| `date` | ローカルの暦日 `YYYY-MM-DD` |
| `startMin` / `endMin` | その日の 0 時からの分（例: 9:30 → 570）。終了 24:00 は 1440 |
| `category` / `location` / `notes` | カテゴリー・場所・メモ |
| `prepTasks` | 準備すること（チェック付き） |
| `status` | `planned`（未記録）／`completed`（完了）／`missed`（未実施） |
| `actualMinutes` | 実際にかかった時間（記録した場合のみ。推測では埋めません） |
| `bufferBeforeMin` / `bufferAfterMin` | 移動・準備の余白（手入力） |
| `fixed` | 時間設計の提案で動かさない |
| `isSample` | 見本データかどうか |
| `history` | 変更の記録（作成・移動・状態の変更など） |

日時を UTC の `Date` で保存せず「暦日＋分」で保存するため、タイムゾーンや夏時間で日付がずれません（夏時間の切り替え日をまたぐテストも含みます）。

## 4. デザインとモーション

- **色**：画面ごとにテーマが切り替わります（`data-theme`）。
  ホーム＝黒・アイボリー・古金／カレンダー＝アイボリー・チャコール・真鍮と鋼／詳細＝深紅／時間設計＝深い青と静かな光／振り返り＝琥珀と青銅の古文書／一日を閉じる＝星空。
- **書体**：欧文の数字・見出しに Bodoni Moda（同梱・オフライン可）、日本語は端末の明朝体・ゴシック体。
- **モーションの語彙**（`src/motion/tokens.ts`）
  - **IRIS** 画面の転換は、押したボタンの位置から新しい画面が円形に開く
  - **ESCAPEMENT** 日常の操作は、素早く動き出してカチリと止まる
  - **ENGRAVE** 装飾や図表は線が描かれていくように現れる
  - **TICK** 一覧は少しずつ時間差で並ぶ
  - **日付窓** 日付を移動すると、変わった桁だけが機械式時計の日付窓のように回転し、ベゼルが回る
  - **私室の扉** 予定を選ぶと、その行が詳細パネルへ広がり、深紅の扉が左右に開く
- **起動演出**：建築の線 → 枠 → 文字盤 → 日付と予定数 → 扉が開いてホームへ。約 3 秒・タブ（セッション）ごとに 1 回・クリックやキーで飛ばせます。
- OS の「視差効果を減らす」設定を尊重し、その場合は起動演出を省略し、動きを短いフェードに置き換えます。

## 5. 操作のヒント

- **新しい予定**：左の柱（スマートフォンは下の中央）の「＋」。カレンダーの空いている時間を押しても作成できます。
- **時刻を動かす**：日表示で予定の右端のつまみ（⋮⋮）をドラッグ。キーボードではつまみにフォーカスして ↑↓ で 15 分ずつ、Enter で確定、Esc で取り消し。
  他の予定と重なる場合は、必ず「再編成の確認」が開きます（後ろの予定を送る／重なったまま動かす／やめる）。他の予定を黙って上書きすることはありません。
- **カレンダーのキー操作**：← → で前後へ、T で今日、D / W / M で日・週・月表示。スマートフォンでは左右のスワイプで移動。
- **削除・移動・提案の適用**の直後は、通知の「元に戻す」で取り消せます。
- **見本データ**：初回は見本の予定（「見本」と表示）が入ります。ホームの案内または設定から、まとめて消去して白紙から始められます。

- `npm run typecheck`・`npm run lint`・`npm test`（単体テスト 31 件）・`npm run build` が成功

## 7. この版でできないこと（正直な制限）

- **通知・アラーム**：予定の時刻にお知らせする機能はありません（iOS の PWA ではバックグラウンド実行に制限があるため、実装していません）。
- **同期・連携**：iPhone の「カレンダー」・Google カレンダーなどとの同期、複数端末間の同期はありません。データはこの端末のブラウザ内だけです。
- **予定の種類**：終日の予定・日をまたぐ予定（例: 23:00〜翌 1:00）・繰り返しの予定には対応していません。
- **祝日**：日本の祝日は表示しません。
- **移動時間**：移動時間の予測や経路の最適化は行いません。余白は利用者が入力した値だけを使います。
- **週表示のドラッグ**：ドラッグでの移動は日表示のみです（週表示・月表示では詳細から時刻を変更してください）。
- **書き出し・バックアップ**：データの書き出し／読み込み機能はまだありません。
- **夏時間**：日本では関係ありませんが、夏時間の切り替え日は「壁時計の時刻」で計算するため、所要時間が実際と 1 時間ずれることがあります。
